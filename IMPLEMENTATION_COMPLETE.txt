FUNCTION EXECUTION FLOW
================================================================================

NLTC_experiment() Execution Sequence:

1. INIT: Clear previous button handlers
   $("#Berth1, #Berth2").off("click")

2. SELECT: Randomly choose question (0 or 1)
   randomQuestion_nltc = Math.floor(Math.random() * nltc_questions.length)

3. RECORD: Log question
   recordTrialData({'phase':'NLTC_question', ...})

4. VIDEO: Display appropriate blocked berth video
   Show: $("#1block") or $("#2block")
   Record: {'phase':'NLTC_video_shown', 'status':'Berth1 is blocked'}

5. UI: Setup text input interface
   Show: $("#wh_textbox"), $("#id_wh")
   Hide: $("#wh_buttons"), buttons

6. WAIT: Create 25-second timeout
   nltcclear = trackTimeout(callback, 25000)

7. INTERACT: Within timeout callback:
   - Show berth selection buttons
   - Attach click handlers
   - Record user action when button clicked
   - Determine reward based on action validity

8. RECORD: Log action results
   recordTrialData({'phase':'NLTC_put_bag', 'status':'#element_id'})
   recordTrialData({'phase':'user_NLTC', 'status':'valid/invalid'})
   recordTrialData({'phase':'Reward_NLTC', 'status':'Reward ±X'})

9. CLEANUP: Handlers automatically cleared by trackTimeout()
   nltcclear variable used to reference this timeout

DATA RECORDING SPECIFICATION
================================================================================

Trial Data Phases Recorded (NLTC-specific):

Phase Name                Type        Example Value
─────────────────────────────────────────────────────────────────
NLTC_question             Status      "question I think Berth1 is blocked..."
NLTC_video_shown          Status      "Berth1 is blocked" / "Berth2 is blocked"
NLTC_put_bag              Status      "#1block_2drop" / "#bag_berth_1"
user_NLTC                 Status      "valid action" / "invalid action" / "valid medium"
Reward_NLTC               Status      "Reward +50" / "Reward -100" / "Reward +30"
NLTC_user_text            Status      [Natural language text from user]

Reward Mapping:
+50   = Optimal valid action (Reward for correct berth selection)
+30   = Alternative valid action (Reward for valid but suboptimal choice)
-100  = Invalid action (Penalty for placing bag on wrong berth)

Also Recorded from sawareness_NLTC() in NLTC conditions:
SA_NLTC                  - User's answer to the situation-awareness question
SA_NLTC_block            - Blocked-berth label
